# Code audit — 2026-10-26 (branch `audit/code-audit-fixes-2026-10-26`)

Four finder agents audited bugs, UX, performance and documentation (read-only).
Four adversarial agents then tried to falsify every finding by re-reading the
cited code, tracing callers and looking for existing guards. Only findings that
survived that challenge were fixed. 29 findings were reported; **none were
rejected outright**, but F1, PERF-1, PERF-2, PERF-4 and PERF-6 were downgraded
to low severity by the adversaries.

## Fixed

### Bugs
- **F1 (low after downgrade)** — PP-DocLayoutV3 GPU acceleration silently fell back to CPU:
  `CustomLayoutModelLoader.TryResolveGpu` treated "GPU descriptor Id == CPU Id" as
  "no GPU variant", but since Core 0.60.2 the V3 GPU route *is* the FP32 CPU descriptor.
  Replaced the Id-equality gate with an explicit Heron/PP-DocLayoutV3 eligibility check.
- **F2** — Closing the active tab disposed its page/minimap `SKImage`s on the UI thread
  before the primary surface rebound, racing the composition thread (#191 class).
  `CloseTab` now takes the wraps via `TakeRetiredImages()` and hands them to the
  primary surface as `RetireImage` messages after the rebind (`IViewportSurface.RetireImages`).
- **F3** — `ReferenceIndex` negative/restart caches were keyed only on analysed-page
  count, so a same-count re-analysis (OCR landing) kept serving a stale miss.
  `Resolve` now drops those caches when any indexed page's analysis instance changed.
  Regression test: `ReanalysisWithSameAnalysedCount_InvalidatesCachedMiss`.
- **F4** — CLI `structure --analyze` and `annotations --include-blocks` ran layout
  analysis with `charBoxes: null` because the text service was only created for
  `--include-text`. It is now created when either flag needs it.
- **F5** — Status-bar `SetZoomPercent` derived its delta from the tab's camera while
  `HandleZoom` acts on the focused viewport; split/tear-off views landed at the wrong
  zoom. Now reads `FocusedViewport?.Camera.Zoom`.
- **F6** — Closing a tab during an annotated-PDF export disposed the model under the
  background export, and failures were only logged. `CloseTab` now refuses while an
  export of that tab is running, and export failures toast.
- **F7 (low)** — CLI `GetRequiredPdf` mistook option values (`--output-dir out`) for
  the PDF path. It now skips values of known value-taking options.
  Regression tests: `CliProgramTests`.

### UX
- **UX-1 (high)** — Ctrl+C/X/V/Z/Y and plain keys were hijacked by the window key tiers
  while typing in text boxes (search, status bar, portal rename). A focused `TextBox`
  now owns its keys; global shortcuts resume when focus leaves it.
- **UX-2** — Rail/page keys pre-empted focused sliders, lists, trees and combos, and
  Space never activated a focused button. Those controls now own arrows/Space while
  focused (buttons: Space only).
- **UX-3** — "Reset All to Defaults" applied and persisted instantly, clearing the VLM
  API key. It now asks first via the new safe-default `ConfirmDialog`.
- **UX-4** — Portal delete was silent and permanent: it now toasts with **Undo**.
  Bookmark delete (no undo API in Core) now confirms via `ConfirmDialog` and toasts.
- **UX-5 (low)** — The automation peer's cached description kept a stale zoom after
  zoom-only changes. Zoom now silently refreshes the description without announcing.
- **UX-6 (low)** — Go-to-page closed silently on invalid input. It now stays open with
  an inline error; -1 is reserved for Escape/Cancel.
- **UX-7** — The external-link confirmation confirmed on Enter from anywhere. Enter
  no longer confirms window-wide; initial focus is Cancel (`ConfirmDialog` shares
  this safe-default pattern).

### Performance
- **PERF-3** — Settings sliders saved the config file and broadcast a full invalidation
  on every drag tick. They now live-apply via `OnSliderChanged` and debounce the heavy
  `OnConfigChanged` by 300 ms (flushed on window close).
- **PERF-5** — The Index pane rendered/encoded every thumbnail synchronously on the UI
  thread before showing entries. Entries now appear immediately and fill in
  progressively in chunks of 8; crops copy pixels into a `WriteableBitmap` instead of
  a PNG encode/decode round-trip; entry view-models are now observable.
- **PERF-7 (low)** — The minimap allocated a new `Cursor` on every pointer move.
  Cursors are cached per type and only assigned on change.
- **PERF-2 (low after downgrade)** — `SyncWindowImages` allocated List+HashSet per
  frame in single-page mode. It now early-outs when no window wraps exist or are wanted.
- **PERF-4 (low after downgrade)** — Continuous-scroll neighbour pages re-sorted their
  annotations every frame. They now use a per-page member-snapshot cache like the anchor.

### Documentation
- **D1 (high)** — `docs/heron-layout-model.md` told users to run
  `./scripts/download-model.sh heron`, which exits 1 ("Unknown model"). Fixed to the
  bare command.
- **D2 (high)** — README/user-guide presented the experimental reading guide as shipped.
  Both now state the Settings ▸ Reading ▸ Experimental enable step.
- **D3** — `CLAUDE.md` described a non-existent `EffectiveGuideFollow` mapping and a
  `WhileShiftHeld` default. Corrected: no mapping exists; the stored default is `Steer`.
- **D4** — User guide attributed margin-crop fit to the `F` key; `F` toggles line-focus
  blur. Fit is `0` only.
- **D5** — The CLI chapter omitted the shipped `references` command. Added a section to
  the user guide and an example to the README.
- **D6** — User-guide CLI tables omitted `--password`/`--pages` (annotations) and
  `--password` (export). Added.
- **D7** — `DISTRIBUTION.md` named release artifacts that don't exist
  (`railreader2-cli-linux-x64`, `RailReader2.Cli.exe`) and omitted the Linux tarball.
  Corrected to `railreader2-cli-linux-x64.tar.gz` / `railreader2-cli-win-x64.zip`.
- **D8 (low)** — User guide said portal sidecars are keyed by PDF path; they are keyed
  by file content (SHA-256) and survive moves/renames. Corrected.

## Survived but deliberately not fixed here
- **PERF-1 (downgraded to low)** — `RenderCamera → UpdateAllLayers` rebuilds layer
  states per camera frame. The adversary showed the expensive builders are already
  cached and no profiling shows they dominate GPU draw. A camera-only fast path is a
  larger refactor of `DocumentView`; it should be driven by a frame-timing trace
  (`RR_FRAME_TIMING=1`), not by this audit.
- **PERF-6 (downgraded to low)** — First freeze-pane activation renders and PNG-encodes
  crops synchronously. It runs once per activation by design (the PNG copy is what
  survives page-bitmap disposal); making it async touches the freeze activation flow
  for a one-time, user-initiated stall.

## Not adjudicated
The docs finder noted two extra low-severity items outside its top-8
(`CLAUDE.md` "scripts/ contains a single helper", `docs/heron-layout-model.md`
`builtin_analyzer` values). They were not put through adversarial verification and
were therefore not changed under this audit's fix-only-survivors rule.
